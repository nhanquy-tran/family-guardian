How a change flows now

Owner picks an issue ─▶ Claude: needs-spec ─▶ spec writer (Sonnet) ─▶ AI review (once) │ SPEC GATE (Claude, max 3 rounds; reads platform notes + main) │ merge build-now when dependencies are merged (max 3 jobs in parallel) │ test writer ─▶ developer ─▶ gates (red, coverage, not weakened, green, check+build) │ any gate fails? test ARBITER (once) ─▶ gates again │ rebase on main ─▶ PR with evidence ─▶ CI, Vercel, migration dry run, AI review (once) │ BUILD GATE (Claude, max 2 attempts) ─▶ merge ─▶ migration applied │ watchdog (30 min): stalled runs restarted, conflicting PRs unblocked

Next improvements (not yet done)

  • Dependency-aware queue: issues declare Depends on #N; a workflow starts the build when the last dependency merges, instead of Claude sequencing by hand.
  • Staging database for previews (Supabase branching) so migration PRs can be tested before merge.
  • Smaller build prompts: pass only the scenario list and touched files to the test writer to cut its 36-turn average.
  • Daily factory digest on the dashboard: items done, cost per item, interventions, open escalations.
