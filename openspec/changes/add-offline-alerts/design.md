# Design

1. **Detection in SQL, sending in the endpoint.** ADR 0010 has cron "find" devices; here cron only triggers and the endpoint calls `find_offline_devices(p_now)` (`last_seen_at <= now - 15 min`, `>= now - 24 h`, no alert with `incident_last_seen_at = last_seen_at`). One tested source of truth, and no device ids travel in the request. The cron request body is empty.
2. **Claim before send.** Per device: insert the alert row, ignoring conflicts. If no row was inserted, skip (another run owns it). Send the e-mails. If there was at least one recipient and every send failed, delete the claim so the next run retries; if at least one succeeded, keep it. Zero recipients: keep the claim, send nothing, log.
3. **Handler seams.** `handleOfflineAlerts({ authorization, secret, mailConfigured, now, store, mailer, log })` with `OfflineAlertStore` (`findOfflineDevices`, `claimAlert`, `releaseAlert`, `listParentEmails`) and `Mailer.send`. The Supabase store lives in `lib/alerts/supabase-store.ts` using `createAdminClient`; parent e-mails come from `auth.admin.getUserById` for the family's `parents` rows.
4. **Auth.** `crypto.timingSafeEqual` over SHA-256 digests of both values. Missing or empty `ALERT_CRON_SECRET` gives `500` and nothing is accepted. Wrong or missing header gives `401` with no DB call. Missing `RESEND_API_KEY` or `ALERT_FROM_EMAIL` gives `500` before any claim.
5. **Mailer.** `POST https://api.resend.com/emails`, bearer key, `text` body only; subject `"<child>: laptop offline"`. Non-2xx or a thrown error is a failed recipient. Logs hold counts only, never addresses, names or ids.
6. **Cron.** `call_offline_alerts()` (security definer, not executable by API roles) reads `app_url` and `alert_cron_secret` from `vault.decrypted_secrets` and calls `net.http_post`. If either is missing it raises a warning and does nothing. `cron.schedule('offline-alerts', '*/5 * * * *', ...)` and `create extension` for `pg_cron`/`pg_net` are guarded so the PGlite harness still loads the migration. Rotating the secret means updating the Vault entry and the Vercel env together; only one value works at a time.
7. **Banner.** `activeOfflineAlerts(rows)` (pure, `lib/alerts/banner.ts`) keeps rows where the device's `last_seen_at` equals `incident_last_seen_at`. `OfflineBanner` is a server component in the dashboard layout that reads `alerts` with the RLS client (existing `alerts_select` policy). Text: "<child>'s <browser> on <OS> has not reported since <time>".
8. **Verification gap.** PGlite has no `pg_cron` or `pg_net`; the job and Vault wiring are checked by hand on production after merge (see factory-learnings on migrations).
