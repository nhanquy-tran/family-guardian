- **Depends on #98**: `public-site` is not in `openspec/specs/` until #98 archives, so the delta uses ADDED only. #98's scenario "Sitemap and robots" says the sitemap is exactly four URLs; this change supersedes it. The developer updates that expectation in `site-routing.test.ts` to the 13 URLs below (a spec-mandated change, not a weakening).
- **Pages** are server components under `apps/web/src/app/[locale]/{setup,faq,help}/page.tsx` with `dynamicParams = false`. Components in `components/site/`: `setup-guide.tsx`, `faq.tsx`, `help.tsx`; they take `messages` as a prop and contain no copy.
- **Messages**: new keys under `setup.*`, `faq.*` and `help.*`. Keep every value a flat string (`faq.q1`/`faq.a1` ...), because #98's key-parity test requires non-empty strings.
- **Support e-mail**: `help.tsx` takes `supportEmail?: string`; only the page reads `process.env.NEXT_PUBLIC_SUPPORT_EMAIL`. Show it only if it matches a simple `x@y.z` pattern with no whitespace. It is inlined at build, so a redeploy is needed after setting it (platform notes). Add the name to `.env.example` if that file exists (names only). `mailto:` does not violate #98's no-`href="http` rule.
- **Install facts**: the guide contains no copy of the install page, but a test compares against `install-instructions.tsx`. Every locale writes the English words "Standard" and "Administrator" in brackets next to the translation.
- **hreflang**: each page exports `generateMetadata` with canonical and `alternates.languages` for its own path, plus `x-default` for `/en/<page>`, and `title`/`description` from `setup.meta.*`, `faq.meta.*`, `help.meta.*`.
- **Accessibility**: native `<details>`/`<summary>`, no JavaScript, `focus-visible:` class on every `<summary>` and link.
