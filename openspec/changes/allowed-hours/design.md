# Design

- **Storage**: `allowed_start`, `allowed_end` as `text` with check `^([01][0-9]|2[0-3]):[0-5][0-9]$`, both null or both not null, `allowed_start <> allowed_end`. `children` uses explicit column grants: `grant update (allowed_start, allowed_end) on public.children to authenticated`. Read `supabase/migrations/` first and never recreate existing objects; timestamp the migration at build time.
- **Version bump**: a `before update of allowed_start, allowed_end` row trigger on `children` sets `new.rules_version = old.rules_version + 1` when a value changed (once per save; do not call `bump_rules_version()`, which updates `children` again). `set search_path = ''`.
- **Window test**: pure `inAllowedHours(hours, nowMs, timezone)` in `apps/extension/lib/hours.ts`; minutes of day via `Intl.DateTimeFormat` with `hourCycle: "h23"` in the timezone (missing or invalid timezone = `UTC`). `start < end`: inside is `start <= t < end`; `start > end` (crosses midnight): inside is `t >= start || t < end`.
- **Next edge**: `nextEdge` steps minute by minute (at most 48 h) to the next minute where the answer flips, so DST changes are handled; `null` when none.
- **Rule**: one dynamic rule, fixed id `ALLOWED_HOURS_RULE_ID = 2000000` (above manual and limit ids), priority 2, `main_frame`, `regexFilter: "^https?://"`, redirect to `/blocked.html?h=<start>` (the time browsing resumes). It never matches the extension's own pages.
- **Reconciling**: `reconcileHours(now)` reads stored `rulesAllowedHours` and `rulesTimezone`, decides paused or not, compares with stored `hoursPaused`, and only on a difference calls `updateDynamicRules` for just this id; stores `hoursPaused` after success; on failure stores nothing and retries at the next alarm. Invalid or missing stored hours count as no window (the contract validates server data; a corrupt local value must not lock the child out).
- **`applyRules` removes every dynamic rule**, so `syncRules` and any other call that replaces rules (including #87's limit rules) must re-add the hours rule when paused. Store `rulesAllowedHours` with the other inputs only after a successful DNR update.
- **Alarms**: a one-shot alarm `hours-edge` at `nextEdge` is (re)created by `reconcileHours` and on start-up; the existing 1-minute alarm also calls `reconcileHours`, so a missed edge self-heals within a minute. It runs without a token check, also while `authState` is `rejected` or the heartbeat fails (the switch is local), and does nothing when no hours are stored.
- **Re-pairing** removes `rulesAllowedHours` and `hoursPaused` and clears the `hours-edge` alarm.
- **Block page**: `describeBlock(search)` in `lib/blocked.ts` (extended by #87) shows `h` only when it matches `^[0-9]{2}:[0-9]{2}$`. No URL is read and nothing is recorded (no domain).
- **Web**: `saveAllowedHours` trims input; both empty clears; one empty, bad format or equal values returns `invalid_hours` before any write; store error returns `failed`. The server action reads `allowed_start`, `allowed_end`, uses the session client and redirects with the error code.
- **Spec collisions**: #87 MODIFIES `daily-limits` and `block-enforcement`; this change only ADDS a new capability to avoid conflicts.
