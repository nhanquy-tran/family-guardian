# Design

- **Storage**: `allowed_start`, `allowed_end` as `text` with check `^([01][0-9]|2[0-3]):[0-5][0-9]$`, both null or both not null, `allowed_start <> allowed_end`. `children` uses explicit column grants: `grant update (allowed_start, allowed_end) on public.children to authenticated`. Read `supabase/migrations/` first and never recreate existing objects; timestamp the migration at build time.
- **Version bump**: a `before update of allowed_start, allowed_end` row trigger on `children` sets `new.rules_version = old.rules_version + 1` when a value changed (once per save; do not call `bump_rules_version()`, which updates `children` again). `set search_path = ''`.
- **Window test**: pure `inAllowedHours(hours, nowMs, timezone)` in `apps/extension/lib/hours.ts`; minutes of day via `Intl.DateTimeFormat` with `hourCycle: "h23"` in the timezone (missing or invalid timezone = `UTC`). `start < end`: inside is `start <= t < end`; `start > end` (crosses midnight): inside is `t >= start || t < end`.
- **Next edge**: `nextEdge` steps minute by minute (at most 26 h: the longest gap between edges plus 2 h for DST) to the next minute where the answer flips, so DST changes are handled; `null` when none.
- **Rule**: one dynamic rule, fixed id `ALLOWED_HOURS_RULE_ID = 2000000` (above manual and limit ids), priority 2, `main_frame`, `regexFilter: "^https?://"` (the `Rule` condition type in `rules.ts` gains `regexFilter`), redirect to `/blocked.html?h=<start>` (the time browsing resumes). It never matches the extension's own pages.
- **Reconciling**: `reconcileHours(now)` reads stored `rulesAllowedHours` and `rulesTimezone`, decides paused or not, and checks `getDynamicRules()` for id 2000000. Only on a difference does it call `updateDynamicRules` for just this id. There is no stored `hoursPaused` flag: DNR rules persist across restarts and are the single source of truth. On failure it changes nothing and retries at the next alarm. Invalid or missing stored hours count as no window and remove the rule (a corrupt local value must not lock the child out).
- **`applyRules` never removes id 2000000** (it removes every other dynamic rule id), so #87's limit path and `syncRules` cannot drop the pause. Only `reconcileHours` owns the rule; `syncRules` stores `rulesAllowedHours` with the other inputs after a successful update and then calls `reconcileHours`.
- **Alarms**: a one-shot alarm `hours-edge` at `nextEdge` is (re)created by `reconcileHours`. It is recomputed at the first alarm after start-up (the existing 1-minute alarm also calls `reconcileHours`, so a missed edge or restart self-heals within a minute; DNR rules persist, so the rule stays in place meanwhile). It runs without a token check, also while `authState` is `rejected` or the heartbeat fails (the switch is local), and does nothing when no hours are stored and no rule is present.
- **Re-pairing** removes `rulesAllowedHours` (in the existing key list). `pairWithCode` has no alarms dependency and does not touch the rule: the next `reconcileHours` finds no hours and removes id 2000000.
- **Priority**: the hours rule has priority 2, above manual rules, so a manually blocked site shows the paused text while paused.
- **Block page**: `describeBlock(search)` in `lib/blocked.ts` (extended by #87) shows `h` only when it matches `^[0-9]{2}:[0-9]{2}$`. No URL is read and nothing is recorded (no domain).
- **Web**: `saveAllowedHours` trims input; both empty clears; one empty, bad format or equal values returns `invalid_hours` before any write; store error returns `failed`. The server action reads `allowed_start`, `allowed_end`, uses the session client and redirects with the error code.
- **Spec collisions**: #87 MODIFIES `daily-limits` and `block-enforcement`. This change ADDS `allowed-hours` and MODIFIES two `block-enforcement` requirements ("Rules are replaced atomically", "Re-pairing resets rule state"), the second written on top of #87's text. Both changes must be merged in order #87 then #89.
